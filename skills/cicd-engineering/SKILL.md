🚀 CI/CD 工程（CI/CD Engineering）
核心问题：代码怎么从仓库到生产？怎么确保每次部署都是安全的？


📌 流水线设计

  标准流水线阶段（从左到右）：

    代码提交
      ↓
    代码质量检查
      Lint / 格式化检查
      代码复杂度分析
      提交信息规范检查（Conventional Commits）
      ↓
    安全扫描
      依赖漏洞扫描（npm audit / pip audit / trivy）
      静态安全分析（SAST）
      密钥泄露检测（git-secrets / trufflehog）
      ↓
    自动化测试
      单元测试（必须通过，覆盖率 >= 阈值）
      集成测试（API 级别）
      端到端测试（关键流程）
      ↓
    构建与打包
      Docker 镜像构建（多阶段构建，最小化镜像体积）
      镜像标签：commit SHA + 语义版本号
      推送到镜像仓库
      ↓
    部署到 Staging
      自动部署到 Staging 环境
      自动化回归测试
      ↓
    部署到 Production
      灰度发布 / 蓝绿部署
      自动健康检查
      监控指标观察
      异常时自动回滚

  流水线设计原则：
    快速反馈：前面的步骤快（Lint < 30s，单元测试 < 3min），慢的步骤放后面
    失败快停：任何一步失败，后续步骤不执行
    并行化：无依赖关系的步骤并行执行（如 Lint 和安全扫描可以并行）
    幂等性：流水线可以重跑，结果一致
    可审计：每次运行都有完整日志和制品记录


📌 部署策略

  滚动更新（Rolling Update）：
    逐步替换旧实例
    配置：maxSurge=25%, maxUnavailable=25%
    适用：无状态服务、大多数场景
    注意：确保新旧版本可以同时运行（向后兼容）
    回滚：kubectl rollout undo

  蓝绿部署（Blue-Green）：
    两套完整环境，切流量一步到位
    回滚：切回旧环境，秒级回滚
    适用：对回滚速度要求极高的场景
    代价：资源消耗翻倍
    实现：通过 Service/Ingress 切换流量指向

  金丝雀发布（Canary）：
    先导 1-5% 流量到新版本，观察指标
    逐步放量：1% → 5% → 10% → 30% → 50% → 100%
    指标异常时自动回滚
    适用：核心服务、大规模用户
    配合：自动化指标检测 + 流量权重控制

  特性开关（Feature Flag）：
    代码层面的功能开关，部署和发布解耦
    可以按用户 ID、百分比、条件开关功能
    适用：灰度测试、A/B 测试、紧急关闭有问题的功能
    注意：开关用完要清理，避免开关债务

  策略选择指南：
    服务数量少、团队小 → 滚动更新
    核心支付/交易服务 → 蓝绿部署
    大流量面向用户服务 → 金丝雀发布
    需要渐进式验证 → 特性开关 + 金丝雀


📌 回滚方案

  自动回滚触发条件：
    健康检查连续失败 N 次（N 根据服务重要性设定）
    错误率超过阈值（如 5xx 比例 > 5%）
    p99 延迟超过 SLO（如 > 2s）
    关键业务指标异常（如订单成功率下降 > 10%）

  回滚执行：
    K8s 滚动更新：kubectl rollout undo deployment/app
    蓝绿部署：切换 Service 指向旧环境
    金丝雀：将流量权重恢复为 0%
    数据库迁移：执行回滚脚本（必须提前准备并测试）

  回滚演练：
    每月至少一次回滚演练（不是等事故发生才第一次回滚）
    记录回滚用时，目标 < 5 分钟


📌 制品管理

  镜像管理：
    标签规范：{service}:{commit-sha}-{build-number}
    语义版本标签：{service}:v1.2.3（用于正式发布）
    latest 标签只用于开发环境，生产环境必须用具体版本
    镜像保留策略：最近 30 个版本 + 最近 90 天

  制品安全：
    镜像扫描：构建完成后自动扫描漏洞（Trivy / Grype）
    高危漏洞阻断：发现 Critical/High 漏洞阻止部署
    基础镜像更新：定期更新基础镜像并重建

  分支策略：
    main/master → 生产环境（通过流水线自动部署）
    develop → Staging 环境
    feature/* → 开发环境（按需部署）
    release/* → 预发布环境
    hotfix/* → 紧急修复，合并到 main 和 develop


📌 CI/CD 工程产出物清单

  部署策略文档（策略选择 + 配置参数 + 回滚方案）
  制品管理规范（标签规范 + 保留策略 + 安全扫描）
  分支策略文档
  回滚演练记录
  流水线性能报告（各阶段耗时 + 优化建议）
