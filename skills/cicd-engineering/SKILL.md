# CI/CD 工程

## 概述

代码怎么从仓库到生产？怎么确保每次部署都是安全的？**Pipeline 是把人类失误挡在生产环境外的最后一道墙。**

## 何时使用

- 搭建或重构 CI/CD 流水线
- 选择部署策略（滚动 / 蓝绿 / 金丝雀 / 特性开关）
- 制品（镜像 / 包）版本管理
- 设计回滚方案与演练
- 流水线性能优化（缓存、并行）
- 集成安全扫描（SAST、依赖漏洞、密钥泄露）

**不要用于：** Docker 镜像构建细节（用 `infrastructure-automation`）、监控告警（用 `observability-ops`）、IaC 资源定义（用 `infrastructure-automation`）。

## 流水线设计

### 标准流水线阶段（从左到右）

```
代码提交
  ↓
代码质量检查（Lint、复杂度、Conventional Commits）
  ↓
安全扫描（依赖漏洞、SAST、密钥泄露检测）
  ↓
自动化测试（单元、集成、E2E）
  ↓
构建与打包（Docker 多阶段构建、镜像标签 = commit SHA + semver）
  ↓
部署到 Staging（自动部署 + 自动化回归）
  ↓
部署到 Production（灰度 / 蓝绿 + 健康检查 + 异常自动回滚）
```

### 设计原则

| 原则 | 说明 |
|---|---|
| 快速反馈 | 前置步骤要快（Lint < 30s，单元测试 < 3min），慢的步骤放后面 |
| 失败快停 | 任何一步失败，后续步骤不执行 |
| 并行化 | 无依赖步骤并行执行（如 Lint 和安全扫描） |
| 幂等性 | 流水线可重跑，结果一致 |
| 可审计 | 每次运行都有完整日志和制品记录 |

## 部署策略

| 策略 | 适用 | 配置 | 回滚 |
|---|---|---|---|
| **滚动更新（Rolling Update）** | 无状态服务、大多数场景 | maxSurge=25%, maxUnavailable=25% | `kubectl rollout undo` |
| **蓝绿部署（Blue-Green）** | 对回滚速度要求极高（核心支付 / 交易） | 两套完整环境，切流量一步到位 | 切回旧环境，秒级回滚；代价：资源消耗翻倍 |
| **金丝雀发布（Canary）** | 核心服务、大规模用户 | 1% → 5% → 10% → 30% → 50% → 100% 逐步放量 | 流量权重恢复 0% |
| **特性开关（Feature Flag）** | 灰度测试、A/B 测试、紧急关闭问题功能 | 按用户 ID / 百分比 / 条件开关 | 开关关闭即可 |

**策略选择指南：**

| 场景 | 推荐 |
|---|---|
| 服务数量少、团队小 | 滚动更新 |
| 核心支付 / 交易服务 | 蓝绿部署 |
| 大流量面向用户服务 | 金丝雀发布 |
| 需要渐进式验证 | 特性开关 + 金丝雀 |

## 回滚方案

### 自动回滚触发条件

| 信号 | 阈值示例 |
|---|---|
| 健康检查连续失败 | N 次（根据服务重要性设定） |
| 错误率 | 5xx 比例 > 5% |
| p99 延迟 | 超过 SLO（如 > 2s） |
| 关键业务指标 | 订单成功率下降 > 10% |

### 回滚执行

| 部署策略 | 回滚命令 |
|---|---|
| K8s 滚动更新 | `kubectl rollout undo deployment/app` |
| 蓝绿部署 | 切换 Service 指向旧环境 |
| 金丝雀 | 将流量权重恢复为 0% |
| 数据库迁移 | 执行回滚脚本（必须提前准备并测试） |

**回滚演练：** 每月至少一次回滚演练（不是等事故发生才第一次回滚）；记录回滚用时，目标 < 5 分钟。

## 制品管理

### 镜像管理

| 规则 | 说明 |
|---|---|
| 标签规范 | `{service}:{commit-sha}-{build-number}` |
| 语义版本 | `{service}:v1.2.3`（用于正式发布） |
| latest 限制 | 只用于开发环境；生产环境必须用具体版本 |
| 保留策略 | 最近 30 个版本 + 最近 90 天 |

### 制品安全

- 镜像扫描：构建完成后自动扫描漏洞（Trivy / Grype）。
- 高危漏洞阻断：发现 Critical / High 漏洞阻止部署。
- 基础镜像更新：定期更新基础镜像并重建。

### 分支策略

| 分支 | 环境 | 部署方式 |
|---|---|---|
| `main` / `master` | 生产环境 | 通过流水线自动部署 |
| `develop` | Staging 环境 | 自动 |
| `feature/*` | 开发环境 | 按需 |
| `release/*` | 预发布环境 | 手动触发 |
| `hotfix/*` | 紧急修复 | 合并到 main + develop |

## 常见错误

| 错误做法 | 正确做法 |
|---|---|
| Lint 和单测在生产部署前才跑 | 在 commit 阶段就跑 Lint，每次 PR 跑单测 |
| 用 latest 镜像部署生产 | commit SHA 或语义版本号 |
| 数据库迁移和应用一起部署 | 迁移先行，验证后再部署应用 |
| 蓝绿环境共用一个数据库 | 数据库独立，迁移独立可回滚 |
| 等事故发生才第一次回滚 | 每月至少一次回滚演练 |
| 镜像保留无策略，仓库爆掉 | 保留最近 30 个 + 90 天 |
| 流水线串行无并行 | 无依赖步骤并行执行 |
