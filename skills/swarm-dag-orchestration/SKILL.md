# 智能体 Swarm 与 DAG 工作流编排

## 概述

复杂的量化投研与工程任务无法依靠单一智能体闭环，必须通过 **Swarm 预设团队** 进行多角色协同，并利用 **有向无环图 (DAG)** 组织任务的依赖关系与数据流。

## 何时使用

*   用户提出复合型量化需求（如：需要计算因子、做回测、审计风险并提供交易计划）。
*   存在多智能体并行的任务（如：因子挖掘与新闻舆情分析并行）。
*   需要严格定义任务节点（Task）的输入与输出数据契约。

**不要用于：**
*   单一且不需要方案设计的基本修改任务（使用常规 10 步流程）。
*   纯粹的前端或后端技术栈开发路由。

## Swarm 预设团队模块

根据业务类型，PMO 可以调度以下 3 类典型 Swarm 团队：

| Swarm 预设名称 | 参与 Agent | 适用场景 |
|:---|:---|:---|
| **趋势跟踪 Swarm** | A股市场分析师、因子研究员、量化策略研究员 | 识别均线突破、量价共振，计算动量因子，输出趋势方案 |
| **基本面价值 Swarm** | 因子研究员、数据工程师、量化策略研究员 | 进行估值分位计算、分析师一致预期扫描，建立价值组合 |
| **全球套利 Swarm** | 新闻舆情分析师、数据工程师、量化策略研究员 | 监测地缘风险、利差变动及链上异常筹码，输出套利计划 |

## DAG 任务图声明规范

任务图必须以 Markdown (在 `docs/dispatch/` 中保存为 `<id>-dag.md`）或结构化 JSON 表示，且必须包含以下要素：

### 1. 节点定义 (Nodes)
每个节点代表一个独立的微任务，必须声明：
*   `task_id`: 节点全局唯一标识
*   `owner`: 执行该任务的 Agent 角色
*   `input_files`: 依赖的输入文件路径
*   `output_files`: 产出的结果文件路径

### 2. 边与依赖 (Edges & Dependencies)
*   定义 `depends_on`: 节点必须在其依赖的所有前置节点 status 变为 `done` 后方可被调度。

### 3. 数据流契约 (Data Contracts)
*   节点产出必须为标准格式。例如：技术分析节点必须产出 `market_report`，因子节点必须产出 `factor_report`，且下游节点只消费这些声明的输出。

## 典型 DAG 拓扑示例

```
                    ┌─────────────────────────┐
                    │    task_data_prepare    │
                    │  (owner: data-engineer) │
                    └────────────┬────────────┘
                                 ▼
                   ┌─────────────┴─────────────┐
                   ▼                           ▼
       ┌──────────────────────┐    ┌──────────────────────┐
       │   task_factor_calc   │    │   task_technical_scan│
       │ (owner: factor-res)  │    │  (owner: market-ana) │
       └───────────┬──────────┘    └───────────┬──────────┘
                   │                           │
                   └─────────────┬─────────────┘
                                 ▼
                    ┌─────────────────────────┐
                    │   task_strategy_combine │
                    │  (owner: strategy-res)  │
                    └─────────────────────────┘
```

## 常见错误

| 错误做法 | 正确做法 |
|:---|:---|
| 在没有前置数据依赖节点完成时提早调度下游任务 | 严格校验 `depends_on` 的所有节点状态是否为 `done` |
| 数据流中传递非结构化的自由文本口径 | 严格使用约定的报告模板作为输入输出介质（如 `factor_report`） |
| 在 DAG 图中引入环形依赖 | 编写完 DAG 后执行拓扑排序自检，确保无循环依赖 |
