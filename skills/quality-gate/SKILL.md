🚦 质量门禁（Quality Gate & Deployment Readiness）
核心问题：系统真的准备好了吗？承受得住高并发负载吗？能上生产吗？


📌 Locust 性能压测与并发门禁

  1. 负载施压核心模型（Locust Test Model）：
    - 每一个服务上线前，必须执行高仿真用户并发测试。
    - 压测脚本必须包含高负荷下的用户真实请求比例（如 70% 读因子值，20% 读取K线，10% 启动回测）。
    - 压测运行指标硬约束（发版准入红线）：
      - **常规 API 端点（无重负载）**：
        - 并发 1,000 UUs (并发用户) 持续 3 分钟。
        - 吞吐量需满足：QPS >= 200。
        - 响应耗时：p95 延迟 < 150ms，p99 延迟 < 300ms。
        - 错误百分比（HTTP 5xx）：<= 0.05%。
      - **重计算 API 端点（如因子回测）**：
        - 并发 50 UUs 持续 5 分钟。
        - 响应耗时：p95 延迟 < 1,000ms。
        - 错误百分比：<= 0.1%。

  2. 自动熔断与发布否决机制：
    - 在 CI/CD 执行 Locust 压测时，若检测到连续 10 秒的 QPS 骤降、502/504 Bad Gateway 频发、或 p95 延迟突破极限阈值，Pipeline 必须立即抛出 `QualityGateFailedException` 中断发布，并一键回滚。


📌 集成测试方法论

  现实检查命令（每次评估必须执行）：
    1. 验证实际构建了什么（检查文件结构和内容）
    2. 交叉检查声称的功能（grep 关键特性关键词）
    3. 运行自动化截图捕获（多设备、多状态）
    4. 运行 Locust 压测脚本收集并发性能 JSON 数据
    5. 审查所有证据（截图 + 压测指标 + 测试结果 JSON）

  QA 交叉验证：
    审查 QA Agent / 测试工程师的发现
    将自动化截图与之前的评估进行交叉引用
    用额外的自动化证据确认或质疑之前的评估
    验证之前报告的问题是否已修复


📌 端到端用户旅程测试

  测试方法：
    从用户视角走完核心业务流程
    每个步骤都记录截图证据
    记录步骤间的过渡是否流畅
    记录数据是否正确传递


📌 跨设备验证

  必须验证的设备尺寸：
    桌面端：1920x1080（主流桌面分辨率）
    平板端：768x1024（iPad 竖屏）
    移动端：375x667（iPhone SE / 标准移动端）


📌 规格合规性检查

  检查方法：
    逐条对照原始需求/规格文档
    每条需求标注：已实现 / 部分实现 / 未实现
    部分实现和未实现的项目附上证据


📌 质量认证评级

  评级标准（残酷诚实）：

    D — 基本功能不可用
      核心流程断裂，无法完成主要任务
      多个 P0 级 Bug，或压测直接卡死进程

    C — 功能可用但问题较多
      核心流程可完成但有明显问题
      多个 P1 级 Bug
      压测指标轻微超标（错误率在 0.5% - 2% 之间）

    B — 良好，有改进空间
      核心流程流畅，仅有 P2/P3 级问题
      性能基本达标（延迟符合 80% 的 SLO）

    A — 优秀，生产就绪
      所有功能完整且稳定，性能极致
      并发压测各项指标（QPS/Latency/Error Rate）全部亮绿灯
      需要压倒性数据和视觉证据才能给出此评级


📌 部署就绪性评估

  评估维度：

    功能完整性：
      所有规格要求是否已实现？
      核心用户旅程是否完整？

    质量稳定性：
      P0 Bug 数量 = 0（必须条件）
      P1 Bug 数量 = 0（必须条件）
      P2 Bug 数量 ≤ 3（可接受但需记录）
      E2E 自动化回归通过率 = 100%

    性能达标：
      Locust 高负载并发压测 100% 通过且无句柄泄漏
      关键页面加载 < 3s (LCP)
      核心 API 响应符合 QPS SLAs


📌 质量门禁产出物清单
  - 核心用户旅程 E2E 测试报告
  - Locust 高并发负载压力测试性能报告（含 QPS、Latency 曲线图）
  - 跨终端兼容性显示适配报告
  - 需求规格合规性 PASS / FAIL 矩阵
  - 残酷诚实的质量认证评级报告与部署就绪 READY / FAILED 结论
