# 质量门禁

## 概述

系统真的准备好了吗？**门禁不是流程表演，而是 P0/P1 数量、压测指标、E2E 通过率的多维硬约束。** 残酷诚实的质量评级比漂亮的报告更重要。

## 何时使用

- 发版准入评审（Pre-release Review）
- 集成测试与端到端（E2E）用户旅程验证
- 跨设备兼容性验证（桌面 / 平板 / 移动）
- Locust 高并发负载压测门禁
- 规格合规性检查（需求 → 实现矩阵）
- 部署就绪性评估与质量评级（A / B / C / D）

**不要用于：** 单元测试编写（用 `tdd-guide` agent）、Bug 修复（用 `systematic-debugging` agent）、CI/CD 流水线配置（用 `cicd-engineering`）。

## Locust 性能压测与并发门禁

### 常规 API 端点（无重负载）

| 指标 | 硬约束 |
|---|---|
| 并发用户 | 1,000 UUs 持续 3 分钟 |
| 吞吐量 | QPS ≥ 200 |
| 响应耗时 | p95 < 150ms，p99 < 300ms |
| 错误率（HTTP 5xx） | ≤ 0.05% |

### 重计算 API 端点（如因子回测）

| 指标 | 硬约束 |
|---|---|
| 并发用户 | 50 UUs 持续 5 分钟 |
| 响应耗时 | p95 < 1,000ms |
| 错误率 | ≤ 0.1% |

### 压测脚本要求

| 要求 | 说明 |
|---|---|
| 真实比例 | 包含高负荷下的用户真实请求比例（如 70% 读因子值，20% 读取 K 线，10% 启动回测） |
| 资源监控 | 同步采集 CPU、内存、句柄数、连接池 |
| 无句柄泄漏 | 压测结束后句柄数必须回到基线 ±5% |

### 自动熔断与发布否决

CI/CD 执行 Locust 压测时，若检测到以下任一情况，Pipeline 必须立即抛出 `QualityGateFailedException` 中断发布，并一键回滚：

| 触发条件 | 阈值 |
|---|---|
| 连续 QPS 骤降 | 连续 10 秒 QPS 跌幅 > 50% |
| 5xx 频发 | 502/504 错误率 > 1% 持续 10 秒 |
| p95 延迟突破极限 | 常规 API > 500ms 持续 10 秒；重计算 API > 3,000ms 持续 10 秒 |

## 集成测试方法论

### 现实检查命令（每次评估必须执行）

1. 验证实际构建了什么（检查文件结构和内容）
2. 交叉检查声称的功能（grep 关键特性关键词）
3. 运行自动化截图捕获（多设备、多状态）
4. 运行 Locust 压测脚本收集并发性能 JSON 数据
5. 审查所有证据（截图 + 压测指标 + 测试结果 JSON）

### QA 交叉验证

| 步骤 | 内容 |
|---|---|
| 1 | 审查 QA Agent / 测试工程师的发现 |
| 2 | 将自动化截图与之前的评估进行交叉引用 |
| 3 | 用额外的自动化证据确认或质疑之前的评估 |
| 4 | 验证之前报告的问题是否已修复 |

## 端到端用户旅程测试

| 方法 | 说明 |
|---|---|
| 用户视角 | 从用户视角走完核心业务流程 |
| 截图证据 | 每个步骤都记录截图证据 |
| 过渡流畅性 | 记录步骤间的过渡是否流畅 |
| 数据正确性 | 记录数据是否正确传递 |

## 跨设备验证

| 设备 | 分辨率 | 适用 |
|---|---|---|
| 桌面端 | 1920×1080 | 主流桌面分辨率 |
| 平板端 | 768×1024 | iPad 竖屏 |
| 移动端 | 375×667 | iPhone SE / 标准移动端 |

## 规格合规性检查

| 步骤 | 内容 |
|---|---|
| 1 | 逐条对照原始需求 / 规格文档 |
| 2 | 每条需求标注：已实现 / 部分实现 / 未实现 |
| 3 | 部分实现和未实现的项目附上证据（截图 / 日志 / 接口响应） |

输出 **PASS / FAIL 矩阵**。

## 质量认证评级（残酷诚实）

| 评级 | 标准 | 处置 |
|---|---|---|
| **D — 基本功能不可用** | 核心流程断裂，无法完成主要任务；多个 P0 级 Bug；压测直接卡死进程 | 阻断发版 |
| **C — 功能可用但问题较多** | 核心流程可完成但有明显问题；多个 P1 级 Bug；压测错误率 0.5%-2% | 阻断发版，需修复 P1 |
| **B — 良好，有改进空间** | 核心流程流畅，仅有 P2/P3 级问题；性能基本达标（延迟符合 80% SLO） | 有条件通过 |
| **A — 优秀，生产就绪** | 所有功能完整且稳定，性能极致；并发压测各项指标（QPS / Latency / Error Rate）全部亮绿灯 | 通过发版 |

**A 级要求：** 必须有压倒性数据和视觉证据才能给出此评级。

## 部署就绪性评估

### 功能完整性

| 检查项 | 标准 |
|---|---|
| 规格要求实现 | 100% 已实现 |
| 核心用户旅程 | 完整无断裂 |

### 质量稳定性（硬约束）

| 指标 | 阈值 |
|---|---|
| P0 Bug 数量 | = 0（必须条件） |
| P1 Bug 数量 | = 0（必须条件） |
| P2 Bug 数量 | ≤ 3（可接受但需记录） |
| E2E 自动化回归通过率 | = 100% |

### 性能达标

| 指标 | 阈值 |
|---|---|
| Locust 高并发压测 | 100% 通过且无句柄泄漏 |
| 关键页面加载 | LCP < 3s |
| 核心 API 响应 | 符合 QPS SLA |

## 质量门禁产出物清单

- [ ] 核心用户旅程 E2E 测试报告
- [ ] Locust 高并发负载压力测试性能报告（含 QPS、Latency 曲线图）
- [ ] 跨终端兼容性显示适配报告
- [ ] 需求规格合规性 PASS / FAIL 矩阵
- [ ] 残酷诚实的质量认证评级报告
- [ ] 部署就绪 READY / FAILED 结论

## 常见错误

| 错误做法 | 正确做法 |
|---|---|
| 压测只跑 30 秒 | 至少 3-5 分钟，覆盖稳定期 |
| 压测脚本用均匀随机请求 | 模拟真实业务比例（70/20/10） |
| Bug 只看 P0 | P0/P1 必须为 0，P2 ≤ 3 |
| 评级宽松、放水通过 | 残酷诚实，A 级需要压倒性证据 |
| 压测通过即认为性能达标 | 还要看句柄泄漏、内存增长曲线 |
| 跨设备只测桌面 | 桌面 / 平板 / 移动三种尺寸都要测 |
| 规格合规性靠记忆标注 | 逐条对照原始规格文档，附证据 |
| 发版后才发现 E2E 失败 | E2E 必须在发版前 100% 通过 |
| 没有发布否决机制 | CI/CD 必须自动熔断，质量不达标立即回滚 |
