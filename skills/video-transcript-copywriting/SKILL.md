# 视频字幕提取与文案加工

## 概述

本 Skill 用于调用本地 `/Users/mshengran/Project/opc-asr` 语音识别（ASR）工具，从音视频文件中提取原始字幕或 Markdown 文本，并根据不同平台的调性进行文案再加工。通过该 Skill，Agent 可以自动化实现从**原始视频/音频文件**到**多平台分发文案（一鱼多吃）**的完整生产管线。

## 何时使用

- 提取视频/音频的字幕（SRT）或原始文本（Markdown）
- 对提取出的字幕内容进行清洗、校对与结构化梳理
- 将原始字幕重写为小红书种草笔记、抖音短视频脚本、微信公众号深度长文或 B 站大纲
- 提炼视频核心观点、精选金句、梳理知识图谱

**不要用于**：视频直接剪辑与视听包装（用 `video-editing-direction`）、热点新闻搜集（用 `news-gathering`）。

## 速查表（Quick Reference）

### ASR 环境检查

在执行转写前，执行以下命令确认本地环境就绪：

```bash
# 1. 确认 Python 环境及依赖（包含 whisper 与 torch）
python -c "import whisper; import torch; print('whisper:', whisper.__version__, 'mps:', torch.backends.mps.is_available())"

# 2. 确认 ffmpeg 是否可用
which ffmpeg
```

### ASR 执行指令

```bash
# 切换到 opc-asr 项目目录
cd /Users/mshengran/Project/opc-asr

# 执行转写（默认输出为 SRT）
python -m scripts.asr "/path/to/video.mp4" --language zh --model turbo

# 执行转写（输出为 Markdown 笔记格式，推荐用于文案加工）
python -m scripts.asr "/path/to/video.mp4" --language zh --model turbo --format md
```

### 核心参数选项

| 参数 | 可选值 | 说明 |
| :--- | :--- | :--- |
| `input` (定位参数) | 绝对路径 / 相对路径 | 输入音频或视频文件的路径（必填） |
| `--model` | `tiny`, `base`, `small`, `medium`, `large-v3`, `turbo` | Whisper 识别模型。默认 `turbo`（平衡速度与质量）；高精度要求用 `large-v3` |
| `--language` | `zh`, `en`, `ja`, etc. | 语言代码。中文使用 `zh`。如果不指定则自动检测 |
| `--format` | `srt`, `md` | 输出格式。`srt` 适合时间戳字幕；`md` 适合文案阅读与加工 |
| `--output-dir` | 自定义目录路径 | 默认输出至 `output/srt/` 或 `output/md/` |
| `--keep-audio` | (无参数) | 若为视频输入，转写完成后保留提取出的临时 WAV 音频文件 |

## 核心规则

### 1. 转写执行流（ASR Workflow）

1. **定位输入文件**：核对用户提供的音视频文件路径。如果未提供完整路径，在当前目录或系统 Downloads 目录中查找。
2. **运行转写**：切换至 `/Users/mshengran/Project/opc-asr` 并执行 CLI 命令。对于长音视频（>30分钟），需明确告知用户转写耗时预估。
3. **读取输出**：读取转写生成的 `.srt` 或 `.md` 文件内容。
4. **错误处理**：若遇到 Whisper 找不到 GPU / MPS 加速或 ffmpeg 报错，自动降级至 CPU 运行并提示用户安装所需依赖。

### 2. 文案提炼与再加工（Rewrite & Adaptation）

读取到原始文本后，首要任务是**纠正 ASR 识别同音错别字**，然后根据目标渠道执行相应的文案加工模版：

#### 核心内容提炼（通用）

| 模块 | 提炼要求 |
| :--- | :--- |
| **一句话主题** | 用 30 字以内概括视频的核心主旨 |
| **结构化大纲** | 提炼 3-5 个核心章节，标明对应的大致时间节点（若使用 SRT 输入） |
| **金句提炼** | 筛选 3-5 句具有极高传播度、情感共鸣或警示意义的发言 |
| **专业词汇校对** | 修正 ASR 对行业术语、人名、缩写的误识别（如 "Claude" 识别成 "克劳德" 或 "Cloud"） |

#### 全文无损清洗与润色（无损清洗）

| 维度 | 规则与格式要求 |
| :--- | :--- |
| **去除废话** | 自动过滤所有的语气词（如：嗯、啊、那个、就是说、然后）和无意义的重复结巴（如：一个）。 |
| **标点与排版** | 根据语义自动添加正确的标点符号。如果表达的是多个并列观点，自动使用无序列表（Bullet points）排版以增强可读性。 |
| **语法修正与润色** | 修正明显的语病和倒装句，将口语化的词汇适度替换为更准确的书面表达，但**绝不可改变用户的原始意思和核心观点**。 |
| **专有名词与多语言** | 准确识别中英混杂的表达，确保行业术语、外语单词（包括英文品牌、缩写等）拼写正确，并在中英文之间自动增加空格。 |
| **纯净输出** | **只输出最终处理好的文本**，不要有任何开场白、解释性话语或“好的”、“已为您修改”、“这是为您清洗润色后的内容”等客套话。 |

#### 小红书种草/干货笔记重写

| 维度 | 规则与格式要求 |
| :--- | :--- |
| **标题格式** | [吸睛痛点/利益点] + [极强情绪词]（20 字以内） |
| **正文结构** | **第一段**：直击痛点 + 强共鸣导入；**第二段**：结构化干货（使用 Emoji 视觉锚点如 ✨/💡/📌，多空行）；**第三段**：引导互动（CTA）。 |
| **排版语境** | 语气口语化、亲切（多用“宝子们”、“姐妹们”），适当插入符合小红书审美的 Emoji。 |
| **标签 (Tag)** | 结尾附带 5-10 个 `#Tag`（核心搜索词 + 泛流量词 + 活动词）。 |

#### 抖音/TikTok 口播脚本重写

| 维度 | 规则与格式要求 |
| :--- | :--- |
| **黄金 3 秒** | 前 3 秒必须抛出极具冲击力的反差论点或利益钩子（Hook），防止用户划走。 |
| **节奏与字数** | 每句台词控制在 10-15 字，节奏紧凑。整篇字数限制在 300-500 字（对应 1-2 分钟视频）。 |
| **视觉/音频提示** | 标注出 [画面切 B-roll]、[BGM 渐强/卡点]、[音效提示] 等导演视听设计（可协同 `video-editing-direction`）。 |
| **文案结构** | 抛出钩子（3s） -> 核心观点 1, 2, 3 -> 行动号召（点赞关注评论）。 |

#### 微信公众号深度长文重写

| 维度 | 规则与格式要求 |
| :--- | :--- |
| **标题风格** | 兼顾深度与好奇心（禁止低俗标题党，重在知识价值与社交货币）。 |
| **正文结构** | **前言**：背景阐述，为什么你需要关心这个问题；**正文**：逻辑递进的 2-3 个核心论点，使用 Markdown 二/三级标题分段；**结语**：深度思考与金句总结，设计转发诱饵。 |
| **视觉引导** | 在段落中对核心结论进行 **粗体加粗** 突出，每 300 字空行，便于快速扫读。 |

#### B 站视频结构化大纲

| 维度 | 规则与格式要求 |
| :--- | :--- |
| **章节划分** | 划分为 [序章 Introduction] -> [核心论点 Body] -> [反转/痛点解决 Climax] -> [尾声 Ending]。 |
| **弹幕互动点** | 在字幕文本情绪高潮处或槽点处，设计 [弹幕预埋点]，如“前方高能”、“保护打在公屏上”。 |
| **三连话术** | 在结尾或核心干货高潮处自然嵌入“一键三连”引导。 |

## 常见错误

| 错误做法 | 正确做法 |
| :--- | :--- |
| **直接使用 ASR 原始错别字** | 重写前必须人工/模型校对一遍高频错字，特别是专有名词和缩写。 |
| **直接复制粘贴大段字幕** | 必须去掉无意义的口头禅（如“然后”、“也就是说”、“那个”），提炼成书面/口语化精炼文案。 |
| **一稿多投** | 小红书和公众号长文必须彻底改变语境、语气、排版格式，不可偷懒。 |
| **未核对 ASR 输出的语言参数** | 若音频为中文，但 Whisper 默认识别失败，需显式传入 `--language zh` 参数。 |
